# Release Notes

This document records user-visible changes in each jkit release. Each version number appears once, listed from newest to oldest.

Unreleased changes are appended to the **current version** section (currently 2.0.2); once released, that section is frozen and a new version section is added above it. Do not rewrite frozen historical versions, and do not open a new `unreleased` heading for the same version number.

## 2.0.2 - 2026-09-14

### Added

**jkit-notify**

- `MarkdownTheme`: 13 rendering themes for Markdown → HTML (default / lark / orangeheart / rainbow / lapis / phycat / blue / vue / green / wheat / ayer / purple / **blog**). The first 12 match doocs/md; `blog` copies alianga.com (Halo · LIlGG_Sakura) article styling — coral links, warm-yellow inline code, dark One Dark fences, ¶/# heading marks and dashed list boxes. `MarkdownTheme.of("lark")` resolves by id, ignoring case and `-` / `_`, and falls back to the default theme for unknown values.
- `MarkdownRenderOptions` plus `Markdown.toHtml(md, options)` / `toDocument(md, options)`: pick theme, code highlighting, inline styles and responsive behaviour in one place. `inlineStyle(true)` writes styles into every tag's `style` attribute for Outlook / corporate mailboxes / WeChat pasting, all of which strip `<head><style>`. `Markdown` is now the public entry point; `NotifyUtils.markdownToHtml(md)` / `markdownToDocument(md, boolean)` / `wrapHtmlDocument(fragment, boolean)` remain and are deprecated.
- Syntax highlighting for fenced code blocks (on by default, disable with `.highlight(false)`): a dependency-free lexer covering java / js / ts / go / python / sql / shell / yaml / properties / json / xml / html. It emits inline `<span style>`, so it renders in both modes; unknown languages fall back to plain escaping.
- `SmtpChannel.markdownTheme(theme)` / `inlineMarkdownStyle(boolean)`: pin the Markdown rendering theme for the SMTP channel (default: classic theme + `<style>` mode).
- Local image embedding: with `MarkdownRenderOptions.imageBaseDir(dir)` (or `SmtpChannel.markdownImageBaseDir(dir)`) every Markdown image that points at a local relative path is converted to `data:image/...;base64,...` and written into `src`, so the body stands alone. Only local paths are touched — `http(s)://` / `//` / `data:` / `cid:` are kept as-is; `./`, `../`, absolute paths and the `file:` prefix all resolve. Missing files, non-images (MIME from suffix and magic bytes) and files above `maxInlineImageBytes` (default 2MB) keep the original `src` — no exception is thrown.
- `MarkdownRenderOptions` also gained `.inlineImage(boolean)` and `.maxInlineImageBytes(long)` to toggle embedding and cap the per-image size.

**jkit-sql**

- `JdbcUrlUtils`: parse JDBC URLs (host / cluster nodes / database / schema / parameters), infer `SqlDialect` via `fromUrl`, return a short type name via `getDbType`, and guess the driver class via `driverForUrl` / `getDriverClassName`. Covers MySQL replication and load-balance, PostgreSQL HA, Oracle SID/Service/RAC, SQL Server, H2, Gauss/openGauss, Dameng, and more. PostgreSQL-family URLs read schema from `currentSchema` (default `public`).
- `com.alianga.jkit.sql.entity.Comment`: first-party table/column comment annotation (`TYPE`+`FIELD`, `value()`). Sits alongside Hibernate `@Comment` and `@SqlTable(comment)` / `@SqlColumn(comment)`; the scanner still matches the simple name `Comment`, so `jkit-sql-model` and similar modules can prefer this package.
- Complex SQL dialect slice L2/L4 harness (Oracle): `ComplexSqlOracleSliceL2*` (jkit-sql) and `ComplexSqlOracleNativeExecute*` (tools-test); 001–300 native execute on oracle19c 300/300 (parseFail=0 / execFail=0); reports under `target/complex-sql-reports/oracle-l2|l4-*`.
- Complex SQL dialect slice L2/L4 harness (MySQL): `ComplexSqlMysqlSliceL2*` (jkit-sql) and `ComplexSqlMysqlNativeExecute*` (tools-test); 001–300 native execute on MySQL `3308/test_db` 300/300 (parseFail=0 / execFail=0); reports under `target/complex-sql-reports/mysql-l2|l4-*`.
- Complex SQL dialect slice L2/L4 harness (SQL Server): `ComplexSqlSqlServerSliceL2*` (jkit-sql) and `ComplexSqlSqlServerNativeExecute*` (tools-test); 001–300 native execute on `jkit_ss_test` (1433) 300/300 (parseFail=0 / execFail=0); reports under `target/complex-sql-reports/sqlserver-l2|l4-*`.
- Complex SQL dialect slice L2/L4 harness (PostgreSQL): `ComplexSqlPostgresSliceL2*` (jkit-sql) and `ComplexSqlPostgresNativeExecute*` (tools-test); 001–300 native execute on `jkit_complex` (5532) 294/300 (parseFail=0; 6 corpus cases need explicit cast for `round(float8,int)`); reports under `target/complex-sql-reports/postgres-l2|l4-*`.
- `SqlGuardedStatement`: T-SQL control-flow guard `IF <expr> <stmt> [ELSE <stmt>]` (e.g. the idempotent drop-table prefix `IF OBJECT_ID('t','U') IS NOT NULL DROP TABLE t;` in SQL Server init scripts). `SqlParser.parseIfGuard` captures the raw condition and the inner body and wraps them in a `SqlGuardedStatement`; its `type()` delegates to the body, so `IF … DROP` still reports as DROP to downstream formatting / cross-dialect conversion. An `IF` at statement start is always parsed as a control-flow guard (in MySQL `IF` is a function, but that never occurs at statement start). `SqlFormatter` / `SqlAstCloner` / `SqlSchemaConverter` all handle it — `sqlserver_init.sql` now parses end-to-end via `parseAll` without the `unsupported statement` error, its 51 guard statements are recognized as DROP, and cross-dialect conversion reports 0 failures. `SqlParserTest.parseSqlServerSql` covers this.

**jkit-core**

- `AESCrypt` GCM authenticated encryption: `encryptGcm(data, key)` / `decryptGcm(data, key)` use `AES/GCM/NoPadding` with a fresh random 12-byte IV prepended to the ciphertext (`IV || ciphertext`); decryption splits it off, so callers never manage IVs. The four-argument `encryptGcm(data, key, iv, aad)` / `decryptGcm(data, key, iv, aad)` take an explicit IV and AAD (authenticated but not encrypted — handy for binding a user id or order number). Also `generateIv()` and the `GCM_CIPHER_ALGORITHM` / `GCM_IV_LENGTH` / `GCM_TAG_BITS` constants. Unlike ECB / CBC, a tampered ciphertext or a wrong key fails loudly instead of decrypting into garbage.
- `EncryptUtils.RSA` OAEP padding: `encryptOaep(byte[], PublicKey)` / `decryptOaep(byte[], PrivateKey)` plus base64 string helpers, using `RSA/ECB/OAEPWithSHA-256AndMGF1Padding`; `buildKeyPair(int keySize)` picks the key size explicitly and `DEFAULT_KEY_SIZE` exposes the default.
- `ULID`: a 26-character Crockford Base32 sortable id in `common.idgenerate`. `next()` / `nextMonotonic()` (adds 1 within the same millisecond, strictly increasing inside one JVM), `parse()` for timestamp and randomness, `toBytes` / `fromBytes` for a compact 16-byte form, `isUlid()` for validation. Parsing applies the Crockford tolerances (`I`/`L`→`1`, `O`→`0`, case-insensitive) and rejects `U` and other illegal characters. Lexicographic order equals generation order, which suits index keys far better than UUIDv4.
- `UUIDv7`: the RFC 9562 time-ordered UUID with the millisecond timestamp in the high 48 bits. `next()` / `nextMonotonic()` (12-bit counter; when it is exhausted inside one millisecond the logical clock advances 1ms so ids never go backwards), `nextString()`, `timestamp(UUID)` to recover epoch millis, `isV7(UUID)` to check. Still a well-formed UUID that fits a `uuid` column.
- `IdGenerator.ulid()` / `uuidV7()` / `uuidV7String()`: facade entries alongside snowflake.
- `DesensitizeUtils`: masking for common data types. Semantic helpers `phone` / `idCard` / `bankCard` / `name` / `email` / `address` / `carNo` / `ip` / `password`, generic `mask(value, keepHead, keepTail[, maskChar])` and `maskAll`, plus `desensitize(value, Type)` for configuration-driven setups (10 `Type` constants). `null` and empty strings pass through without throwing; when `keepHead + keepTail` covers the whole value only the first character survives instead of returning the plaintext; `password` always emits six mask characters so the password length stays hidden.
- `HttpClient`: instantiable HTTP client (next-plan §4). `HttpUtils` is a process-wide global facade where every `setXxx` mutates the global default and threads overwrite each other; `HttpClient` gives each instance its own config (timeouts / proxy / SSL / CookieJar / engine / interceptors / fakeIp / default Content-Type) with no cross-instance or cross-thread pollution. `builder()` seeds from the current global defaults and is chainable; `shared()` returns the global default singleton, equivalent to the `HttpUtils` static API. Isolation uses a thread-local that propagates the instance config down the send chain, so no global lock is needed. `HttpConfig` gains `copy()` so instances get an independent config snapshot.
- `JwtUtils`: JSON Web Token issue and verify (the JWT half of next-plan §4 "JWT + encryption defaults"). JDK-only — `java.util.Base64` url variant plus `javax.crypto` HMAC / RSA-SHA256, zero third-party dependencies. `createHs256(secret, payload)` / `createRs256(keyPair, payload)` issue tokens; `parseHs256(secret, token)` / `parseRs256(publicKey, token)` verify and return the payload (auto-decoded into a `Map`); `withExp(minutes)` / `withNbf(minutes)` / `withIssuer` / `withAudience` are claim shorthands, and `exp` / `nbf` / `iat` support both millisecond and second units (`expAt(Instant)` / `expSeconds(long)`). Verification is strict: a bad signature, wrong key, expiry, not-yet-valid, or tampered payload all fail; `alg=none` is explicitly rejected and algorithm confusion is blocked (an HS256 token cannot be opened with an RS256 public key); base64url is unpadded and the payload may be any JSON object (nested and standard registered claims included). `JwtUtilsTest` (16 cases) covers HS256 / RS256 round-trips, wrong key, tampering, expiry, not-yet-valid, claim retention, `alg=none` rejection, and base64url edges.
- `JSONPatch`: JSON Patch (RFC 6902) apply utility (the Patch half of next-plan §4 "JSON Patch / Schema `required` alias"; the `required` alias already landed earlier in 2.0.2). `apply(String doc, String patch)` parses and serializes for you; `apply(Object, List)` mutates the parsed `Map`/`List` in place and returns it. Supports `add` / `remove` / `replace` / `move` / `copy` / `test`, uses JSON Pointer (RFC 6901, with `~1`→`/` and `~0`→`~` decoding), and `test` compares numbers by value (`1` equals `1.0`). A malformed `path`, out-of-range index, `remove`/`replace` on a missing member, or a failed `test` throws `JSONPatchException` (a subclass of `JSONException`). `JSONPatchTest` (32 cases) covers every operation, array insert and the `-` end token, root replacement, pointer escaping, numeric equality, and the various illegal-input rejections.
- `Retryer` / `CircuitBreaker`: generic (HTTP-agnostic) resilience primitives (next-plan §4 "韧性抽包"). `Retryer.retry(Callable, RetryConfig)` retries a failing task a limited number of times with exponential backoff + jitter, retries all non-`Error` exceptions by default, and `retryOn(Predicate)` / `retryOn(Class)` narrow the scope; `CircuitBreaker` is a `CLOSED`→`OPEN`→`HALF_OPEN` state machine that opens after consecutive failures, probes after a cooldown, and closes on success, with atomic internal state safe for concurrent use. Both are pure JDK, zero-dependency. `RetryerTest` (8 cases) + `CircuitBreakerTest` (7 cases) cover first-try success, success-after-retry, exhaustion rethrowing the last exception, predicate filtering, no-retry-on-Error, backoff cap, open threshold / immediate OPEN rejection / half-open after cooldown / half-open recovery and re-open / success reset.
- `com.alianga.jkit.html`: lightweight HTML parsing and CSS selection (next-plan §4 "轻量 HTML", replacing the removed Jsoup), zero-dependency. `Html.parse` yields a `Document`; the DOM offers `Element` / `TextNode` / `Comment` / `Elements`, with `select` / `selectFirst` / `text` / `attr` / `innerHtml` / `outerHtml` / `children` on elements; the selector supports type, `#id`, `.class` (including `.a.b`), attribute selectors `[attr]` plus `=` `/` `^=` / `$=` / `*=` / `~=` / `|=`, descendant and child combinators, comma grouping, and `:first-child` / `:last-child` / `:only-child` / `:root` / `:empty` / `:not()` / `:nth-child(an+b)`; `Html.escape` / `Html.unescape` handle entities. The parser tolerates malformed HTML (implicit closing of unclosed tags, void elements never pushed, truncated forms like `<div/` terminating safely, script/style treated as raw text). `HtmlTest` (14 cases) covers structure, every selector kind, pseudo-classes, void-element serialization, text extraction, tolerance, and entity escaping.

- `com.alianga.jkit.html` fidelity pass (differentially validated against Jsoup 1.18.1: 86 of 93 "HTML + selector" cases produce identical results): **parser** — implicit `html`/`head`/`body` skeleton, HTML5-scoped auto-closing of optional end tags (`p`, `li`, `dt`+`dd`, `td`+`th`+`tr`, `option`, `rt`+`rp`, `thead`+`tbody`+`tfoot`, including a `p` buried under inline elements), implicit `tbody` inside `table`, unquoted attribute values now accept `/` and `&` (`href=/x?a=1&b=2` is no longer truncated), and a new `DataNode` so `script`/`style` content serializes unescaped; **selectors** — adjacent `+` and general `~` sibling combinators, `:nth-last-child` / `:nth-of-type` / `:nth-last-of-type` / `:first-of-type` / `:last-of-type` / `:only-of-type` / `:contains` / `:containsOwn` / `:matches` / `:matchesOwn`, attribute `[attr!=v]`, case-insensitive pseudo-class names, and illegal selectors (`h1 @ p`, `p ~ + p`, `p:not()`) now throw `SelectorException` immediately — previously an unknown character caused an infinite loop; **text** — `text()` now matches Jsoup (space between block elements, whitespace collapsing, trimming including `&nbsp;`), plus new `ownText()` / `nextElementSibling()` / `previousElementSibling()` / `elementSiblingIndex()`, and `nodeText()` returns the un-normalised original; **entities** — new `Entities` table with ~200 frequently used named entities (`&copy;`, `&mdash;`, `&hellip;`, …). `HtmlTest` grew to 32 cases, including a regression case asserting that illegal selectors throw instead of hanging.

- `com.alianga.jkit.html` performance pass (benchmarked on the same machine against Jsoup 1.18.1: 3 warmup rounds, 7 timed rounds, median taken, `-Xms1g -Xmx2g`; Jsoup is used for benchmarking only and is not a project dependency). **Memory** — `Element` attributes moved from a `LinkedHashMap` to parallel `String[]` arrays (keys / values / count), child and attribute containers are lazily allocated, and a new `Names` intern table shares tag and attribute name strings: retained heap for 200 large (300 KB) DOMs dropped from 506.9 MB to 268.0 MB (Jsoup 241.5 MB), narrowing the gap from +110% to +11%. **Parsing** — head / body membership in the open-element stack is now a cached index instead of an O(depth) linear search, start-tag attributes are written into a reusable buffer instead of allocating a Map per tag, `Character.isLetter` / `isWhitespace` / `isLetterOrDigit` replaced with local ASCII checks, and `trim().isEmpty()` replaced by a hand-written scan: parsing a 300 KB page went from 2.161 ms to 1.775 ms, i.e. from 12% slower to 3%–28% faster. **Selectors** — traversal changed from "collect `allElements` then dedupe via `LinkedHashSet`" to direct recursion (no intermediate list, no iterator), `Compound.matches` iterates by index, attribute selectors halve their scan count (one lookup instead of `hasAttr` + `attr`), `~=` no longer uses a regex `split`, tag names are normalised at parse time so `equalsIgnoreCase` degrades to `equals`, and parsed selectors are cached by access order with a cap of 256 (Jsoup caches its queries too): on a medium (30 KB) page selectors went from up to 5x slower to 1.6x–4.1x faster, and on a large page they are roughly on par (0.91x–1.15x). `HtmlTest` still passes 32/32 and the Jsoup differential still reports 112 identical / 7 known differences — identical to the pre-optimization run, so no behaviour regressed.

- `com.alianga.jkit.html` selector index: `Document` now carries a lazy id / class / tag index (key prefixes `t:` / `#:` / `.:`, built on first query and reused afterwards). `doc.select(...)` / `doc.selectFirst(...)` no longer walk the whole tree every time — they fetch candidates and verify them. Key priority is id > class > tag name: `div.foo` keys on `.foo`, `a[href^=/p/]` keys on `a` (tag names are index keys too, so attribute queries benefit as well), and only pure attribute / pseudo-class queries (`[data-x]`, `:empty`) fall back to a full traversal. When the query root is a child element (`article.selectFirst("a.post-title")`) the traversal still runs, because candidates are document-wide and testing each one for subtree containment costs more than walking a small subtree — so in extraction code prefer hoisting queries to document level. The index is only this cheap because the DOM is immutable once parsed (no setters, no way to add or remove children): it is built once and can never go stale, so it needs no invalidation logic at all. Measured (synthetic corpus, order-balanced timing): selectors go from 1.3x–2.2x to 4.6x–80x on medium pages and 8.6x–749x on large ones, with end-to-end at 1.89x; on the real alianga.com site the index parse is 1.74x, parse + extract-all-fields 1.73x, and the four extraction selectors run 4.5x–37.1x. Retained heap is still 202.6 MB for parse-only (a DOM that is never queried never builds the index — identical to before), rising to 209.1 MB vs Jsoup's 181.0 MB once a query runs; the index costs roughly 3.5% of one DOM. `HtmlTest` grew from 34 to 39 cases with `indexAndTraversalReturnTheSameElements` (runs the same queries at document level via the index and at element level via traversal, asserting `assertSame` on every element), `indexKeepsDocumentOrder`, `repeatedIdAndMultiClassAreIndexedCompletely`, `missKeyYieldsEmptyInsteadOfCrash` and `indexIsBuiltOnceAndReused`; the Jsoup differential still reports 112 identical / 7 known differences and all 5 fields of all 10 real-site posts still match.

### Changed

- `jkit-core`: `EncryptUtils.RSA.buildKeyPair()` now generates **2048-bit** keys by default (was 1024). 1024-bit RSA no longer meets current baselines (NIST and PCI-DSS both require ≥2048); call `buildKeyPair(1024)` when the old length is truly needed, and anything below 512 bits throws `IllegalArgumentException`.
- `jkit-core`: `DESCrypt` and `EncryptUtils.DES` are `@Deprecated` (56 effective bits are brute-forceable, and neither ECB nor CBC detects tampering). Both still work for reading legacy ciphertext; use `AESCrypt.encryptGcm` for anything new.
- `jkit-notify`: Markdown rendering now lives on `Markdown` (`toHtml` / `toDocument` / `wrapDocument`). The 2.0.1 `NotifyUtils.markdownToHtml(md)` / `markdownToDocument(md, boolean)` / `wrapHtmlDocument(fragment, boolean)` methods remain and are `@Deprecated`. `toDocument` / `wrapDocument` generate the stylesheet from the active theme instead of a hard-coded CSS block; the default look shifts slightly (16px body, 1.75 line height, richer heading and table styling) and code highlighting is on by default.
- `jkit-notify`: fixed the macOS-window code blocks (blue / vue / ayer) where the three top dots overlapped the first code line. Both the stylesheet and the inline style now reserve 36px on top (previously only `padding-top:34px`, which was wiped out by the inline style and by the shorthand `padding` in the mobile media query).
- `jkit-notify`: mobile media-query rules now carry `!important` — in inline mode a tag's `style` attribute outranks the stylesheet, so without it the whole mobile adaptation was dead. The mobile block also shrinks heading sizes, tightens table cell padding, caps image width and enables inertial table scrolling; it no longer overrides the code block's top padding with a shorthand `padding`.
- `jkit-notify`: quotes with the decorative quote mark (purple / lapis / orangeheart) now place the mark inside a 2.6em left gutter instead of on top of the text, and inline-mode quote padding matches the stylesheet (previously the bar and filled variants produced identical output).
- `jkit-notify`: **the column layout moved onto the shell's own `<div class="jkit-md">` container** (it used to hang off `body`). Gmail, QQ Mail and similar clients strip `<html>/<head>/<body>`, so `max-width` / `padding` written on `body` vanished with the tag and the text filled the whole reading pane. Width, padding, font, colour and line height are now inlined on that div.
- `jkit-notify`: fixed the complete HTML document pinning the column to the left in a browser — `body` no longer carries `max-width` (the shell inlines `margin:0` on body so the background fills the viewport; the width cap stayed, the centering margin was overridden). Column width and `margin:0 auto` hang only off `div.jkit-md`; the mobile media query also pads that container alone.
- `jkit-notify`: default column width 720 → **820px**; desktop padding is now `24px 16px` and mobile `12px 8px` (almost no horizontal gutter). The container width comes from the theme's own `maxWidth` token instead of being hard-coded in a media query.
- `jkit-notify`: images are centred and pick up the theme corner radius (`display:block;margin:1.4em auto`), sharing the same width as paragraphs, code blocks and tables — narrowing images alone made them misalign with the text. Desktop code blocks get 18px horizontal padding and a 1.7 line height.
- `jkit-notify`: raw HTML `<img>` in the Markdown (common in WeChat articles as `<img src="..." width="100%" />`) is sanitised and passed through instead of being escaped to `&lt;img&gt;`. Only src/alt/title/width/height/class/loading are kept; event handlers such as `onerror` are dropped and a `javascript:` src becomes `#`. Other HTML tags are still escaped.
- `jkit-sql`: the row-level inject implementation is renamed from `SqlTenantRewriter` to `SqlInjectRewriter` (2.0.2 has not shipped, so the old name is not kept). Tenant is one scenario; class and method names no longer say tenant.
- `jkit-sql`: complex-SQL regression gates tightened — L1 parse and L3 convert-then-parse moved from "≥95% / ≥90%" to 100%; L3 grew from 5 direction pairs to the full 4×3 matrix (3600 conversions, adding PostgreSQL as a source); L2 gained a hard "no loss of significant parentheses" assertion. The 8 dialect slice L2 tests now extend `AbstractComplexSqlSliceL2Test` and only declare dialect and id range (about 1100 fewer duplicated lines).
- `jkit-sql`: `SqlIdentifier` now tracks quoting per name part (`markQuotedPart` / `isPartQuoted` / `quotedParts`). Previously a single `quoted` flag covered the whole identifier, so `c."LEVEL"` round-tripped to `"c"."LEVEL"` — the quotes leaked onto the table alias, and Oracle rejects it with `ORA-00904` because `"c"` does not match alias `C` (15 of 900 corpus cases failed on real databases). `SqlParser` marks per part, `SqlAstCloner` copies the bitmap, `SqlFormatter` emits per part; identifiers built by rewriters have no per-part info and fall back to the whole-identifier flag, so behaviour is unchanged there.
- `jkit-sql`: L2 structure comparison grew from 6 statement-level fields to a deep walk — `ComplexSqlReports.deepStructureDrift` recursively compares select-item count / WHERE / GROUP BY / HAVING / ORDER BY / FROM / DISTINCT / UNION / LIMIT. A dropped select item or a vanished WHERE clause used to go unnoticed.
- `jkit-sql`: `SQL.bind` / `bindNamed` string entry points no longer clone the tree just produced by parse; visitor dispatch puts SELECT/expr types first; bind values allocate less (index over Iterator, fast-path strings without quotes, interned small-int text). The AST entry points still clone-then-mutate.
- `jkit-sql-auto`: `SqlAutoDialects.fromUrl` / `driverForUrl` now delegate to `JdbcUrlUtils` (more URL prefixes: Gauss, Kingbase, Hive, ClickHouse, Trino, …).

### Fixed

- `jkit-core`: end-tag lookup for `script` / `style` / `textarea` in `com.alianga.jkit.html` was O(tags × document length) — every lookup ran `toLowerCase()` over the whole document before `indexOf`. A synthetic page with one `script` hid it, but a real 70 KB index page with 24 `script` tags parsed in 3.929 ms, **14x slower than Jsoup**. It now scans character by character and compares with `regionMatches(true, …)`, allocating nothing: the same page drops from 3.929 ms to 0.179 ms (21x faster), and the synthetic large page parse drops from 1.775 ms to 1.060 ms. End-tag casing, spaced forms like `</script >`, and `<` inside content are covered by the `rawTextCloseTagIsCaseInsensitive` regression.
- `jkit-core`: `pre` context did not propagate whitespace preservation in `com.alianga.jkit.html`. Newlines inside `pre > code` were collapsed to spaces (`text()` on `<pre><code>int a = 1;\n    int b = 2;</code></pre>` returned `int a = 1; int b = 2;`), corrupting code-block extraction. It now matches Jsoup: walk up through parents, preserve raw whitespace once a `pre` / `textarea` is hit, and stop preserving when a non-inline element appears in between — so `pre > code > span` preserves while `pre > div > code` does not. Covered by the `preContextKeepsNewlines` regression.
- `jkit-core`: the JSON Schema `required` keyword was parsed but never enforced — a payload missing a field declared the standard way still passed `validateSuccess`, a silent failure. `JSONNode#validateSchemaObject` now checks that every field listed in `required` exists (standard semantics: presence is enough, and a `null` value counts as present; `type` still decides type mismatches). `required` works without `properties` and applies to nested objects. The library's own `must` keeps its meaning (field present and not `null`), and when both appear both must hold.
- `jkit-sql`: round-tripping no longer drops expression parentheses. `(a - b) / c` used to come back as `a - b / c`, `-(a + b)` as `-a + b`, and `ROUND((SELECT …), 2)` as `ROUND(SELECT …, 2)` — the evaluation order changed, and the last one is not even valid SQL. The parser now keeps the source parenthesized flag, and a scalar subquery passed as a function argument keeps its parentheses. 172 of the 1200 complex-SQL corpus cases were affected; L2 text fidelity rose from 45.75% to 91.83%, and a new gate rejects any loss of significant parentheses (collapsing a redundant `(col)` does not count).
- `jkit-sql`: classic Oracle ROWNUM pagination of a UNION / INTERSECT / EXCEPT / MINUS that has an `ORDER BY` now wraps as `SELECT * FROM (set-op) ORDER BY …` before the ROWNUM layers, so Oracle does not raise `ORA-00904` when ordering a set-op by column aliases inside a subquery. The outer select of a double wrap projects the original columns only and no longer returns the helper `RN` column (a source `SELECT *` still includes `RN`).
- `jkit-sql`: `SqlNode.toString()` now uses MySQL identifier quotes (backticks) by default, matching `SQL.toSqlString`. `addComment("text")` and compact `--` line comments are emitted as block comments so they cannot swallow the following statement. Bare `addHint` text is wrapped as a slash-star-plus hint. Use `SQL.toSqlString(stmt, dialect)` for another dialect.
- `jkit-sql-auto`: `SqlAutoInspector` now resolves schema when checking whether a table exists. If unset, it uses `Connection.getSchema()`; with no connection (dry-run) or an unsupported driver, it parses the JDBC URL. PostgreSQL / Gauss default to `public`, SQL Server to `dbo`, Oracle / Dameng fall back to the username. This avoids treating a same-named table in another schema as present, or emitting ALTER for a table missing from the current schema.
- `jkit-curl-codegen`: curl parse warnings (e.g. "unsupported option --digest, skipped") were dropped on the generation path; they are now merged at the front of `GeneratedCode.notes()`, ahead of the generator's own notes.
- `jkit-curl-codegen`: generators no longer silently drop content. `py-requests` now emits a real `files=` dict for multipart and passes it to the request (file uploads previously vanished); `py-httpx` gained multipart / file bodies; `js-fetch` / `js-axios` emit a readable fs example with the file path for `-T` bodies instead of a bare `undefined`; `go-nethttp` / `csharp-httpclient` generate real multipart code (`mime/multipart` / `MultipartFormDataContent`) and file bodies (`os.Open` / `File.ReadAllBytes`); `php-curl` emits `CURLFile` for multipart. ## 2.0.1 - 2026-09-13

The repository has been split into multiple modules. This release delivers `jkit-sql`, `jkit-sql-auto` (with Spring Boot 2 / 3 starters), `jkit-notify`, `jkit-notify-extra`, and `jkit-curl-codegen` alongside the parent POM. The coordinate `com.alianga:jkit` still refers to `jkit-core`.

- `jkit-core`: when the response declares `Content-Encoding: gzip` but the body is empty, JDK 8 no longer throws `EOFException`; returns an empty stream (underlying connection is still reclaimed on close).
- `jkit-sql`: when a subclass and a `MappedSuperclass` / parent class both declare a same-named column, only the subclass field is kept, preventing PostgreSQL `column specified more than once`.
- `jkit-sql`: `@GeneratedValue(generator="system-uuid")` / `GenerationType.UUID` / non-integer `@SqlGenerated` no longer produce `AUTO_INCREMENT` / `IDENTITY` (PostgreSQL would syntax-error on `IDENTITY` for a `VARCHAR` primary key).
- `jkit-sql`: auto-generated index / sequence / trigger names are truncated to the dialect identifier length limit (classic Oracle 30 characters; when exceeded, the prefix is kept plus a 4-character hash). Unnamed indexes changed to `{table}_{col}_idx`; multiple unnamed indexes on the same table no longer collide. Public APIs: `SqlDialectSpec.maxIdentifierLength` / `fitIdentifier`.
- `jkit-sql`: `SQL.format` pretty mode now wraps and indents `CREATE TABLE` columns (`toSqlString` / compact still single-line).
- `jkit-sql`: `GROUP_CONCAT` without an explicit `SEPARATOR` no longer loses the separator when rewriting to `STRING_AGG` / `LISTAGG`; MySQL `MODIFY` / `CHANGE` rewritten to PG/ANSI/H2/PRESTO no longer duplicate the column name.
- `jkit-sql`: `SUBSTRING` / `LEFT` / `RIGHT` rewritten per dialect (PG/MySQL/H2 use `FROM n FOR m`; SQL Server/SQLite/Hive/ClickHouse use comma form; negative start rewritten with `LENGTH/LEN`); Dameng bare SELECT appends `FROM dual`.
- `jkit-sql`: `SqlDialectWrapper` no longer delegates derived methods (`identQuoteClose` / `quoteIdent` / `pipesAreConcat` / `preferredLimitStyle`); subclass overrides of primitives now automatically cascade to derived capabilities.
- `jkit-sql`: rewrite fidelity — `NATURAL JOIN` no longer loses its modifier; `RENAME TABLE` no longer writes illegal `ALTER TABLE`; `ADD UNIQUE KEY` no longer drops `UNIQUE`; `IGNORE` / `LOW_PRIORITY` / `HIGH_PRIORITY` on `INSERT/UPDATE/DELETE` are preserved in the AST and rewritten; non-bare-identifier aliases are force-quoted.
- `jkit-sql`: `tables()` now captures `CREATE TRIGGER` / `CREATE TABLE … LIKE` / `RENAME TO` / multi-table `OPTIMIZE|ANALYZE`; database names, routine names, and CTE names are no longer miscounted. Comment-only / blank-only input is classified as `OTHER` instead of throwing `empty SQL`.
- `jkit-sql-auto`: on classic Oracle, auto-generated `CREATE INDEX` names exceeding 30 characters are now truncated to avoid ORA-00972.
- `jkit-curl-codegen`: R (httr2) now uses `req_perform()`; PowerShell 5.1 restricted headers / cookie commas / Chinese encoding fixed; Windows curl split into cmd (`shell-curl-windows`) and PowerShell (`shell-curl-powershell`) generators.

## How to Record Future Versions

1. Change the `<version>` in the root `pom.xml` (`jkit-parent`) to the new version number; child modules inherit it. Update the README header and dependency examples, and the version printed by `Main.java`.
2. Insert the new version **above** the current latest-version section, with today's date (`YYYY-MM-DD`). **Each version number gets exactly one H2 heading**; before release, append new items to that section — do not open a separate `## x.y.z / unreleased`.
3. Document caller-visible changes under **Added / Changed / Fixed / Build** (use bold module names for grouping in multi-module projects). Do not simply paste git titles, and do not record internal milestones or competitor-coverage rounds (those go in `docs/sql.md` / `docs/next-plan.md`).
4. Add `@since x.y.z` to javadoc for newly added public APIs.
5. Leave historical versions in place; do not rewrite old entries as new versions.

Template:

```markdown
## x.y.z - YYYY-MM-DD

### Added
- ...

### Changed
- ...

### Fixed
- ...

### Build
- ...
```

Omit any section heading when there are no changes in that category.
