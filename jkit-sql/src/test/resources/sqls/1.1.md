### 逻辑分析与思考过程

1.  **分析用户需求**：用户希望为之前提供的10个复杂业务SQL生成对应的初始化SQL脚本。这意味着我需要为每一个查询编写 `CREATE TABLE`（数据定义，DDL）和 `INSERT INTO`（数据操作，DML）语句，以便用户可以直接在数据库中运行并测试这些查询。
2.  **识别信息缺口**：我需要从之前的10个SQL中反推表名、列名以及合适的数据类型。由于之前的SQL已经明确了字段，这里没有缺失的外部信息。我具备所有主流数据库（MySQL, Oracle, PostgreSQL, 达梦）的语法知识，因此不需要调用外部搜索工具。
3.  **制定策略**：
    *   按1到10的顺序，为每个查询单独提供一套初始化脚本。这样可以避免不同查询中同名表（如 `sales` 表在Q1、Q3、Q9中字段略有不同）发生冲突。
    *   针对不同的数据库方言调整语法。例如，Oracle 中使用 `NUMBER` 和 `VARCHAR2`，且不支持 `DROP TABLE IF EXISTS`；MySQL 中遇到关键字 `date` 需要用反引号 `` `date` `` 括起来。
    *   插入具有代表性的测试数据，确保原SQL执行后能看到明显的效果（例如，Q9中插入一条异常高的销售数据，Q5中插入消费超过1000的客户数据）。

---

以下是为这10个复杂SQL量身定制的初始化脚本（DDL 和 DML）。为了避免表名冲突，建议按顺序在对应的数据库中单独测试。

### 10. Oracle - MERGE 语句进行 upsert 操作
```sql
-- DROP TABLE target_table;
-- DROP TABLE source_table;

CREATE TABLE target_table (
    id NUMBER PRIMARY KEY,
    value VARCHAR2(50),
    update_date DATE,
    create_date DATE
);

CREATE TABLE source_table (
    id NUMBER PRIMARY KEY,
    value VARCHAR2(50)
);

-- 初始化目标表数据
INSERT INTO target_table VALUES (1, 'Old_Value_1', NULL, SYSDATE - 1);
INSERT INTO target_table VALUES (2, 'Old_Value_2', NULL, SYSDATE - 1);

-- 初始化源表数据
INSERT INTO source_table VALUES (1, 'New_Value_1'); -- ID为1，将触发 UPDATE
INSERT INTO source_table VALUES (3, 'New_Value_3'); -- ID为3，将触发 INSERT
COMMIT;
```
