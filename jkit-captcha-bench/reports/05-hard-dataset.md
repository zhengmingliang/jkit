# 阶段五：全字符表难版数据集与识别优化

数据集按 9185960/a54af95 的新版生成器重建（种子 20261101）：纯英文/纯数字放开到完整字母表与
0–9，画布高度 50/58、按文本长度定宽，旋转 0°/8°，噪点压在笔画上，干扰线穿越字符，非算术类
底色加入深色，算式不再绘制 `=?` 尾巴。四类各 25000 张，与阶段四的收窄字形数据集不可比。

## 追加：算术运算符修复（81.16% → 81.98%）

基线等长错误里运算符混淆约 1700 次（+→x 439、/→l 394、*→x 329、/→7 251、-→s 104）。解剖发现
两条路径：

1. **模型掺字母**：AUTO 模式下模型拿全字母数字表，算式里的斜杠被读成 l、减号读成 s，
   CaseAlign 合并时带进算式。修复：结果类型为算术且模板串确有运算符时，把模型字符集限到
   算术表（裸数字串不限制，保住模型对深色字母/混合图的字母救援——无证据门槛时混合类会掉
   4pp，实测否决）。
2. **CaseAlign 覆盖正确运算符**：模板串常带裂开数字的垃圾（7 裂成两块，一块丢一块误标成
   斜杠）导致算不出值才进模型合并，合并又把模板里正确的 `*` 覆盖成模型的 `x`。修复：
   repairOperators 把模板中的加减乘除按位还原，在所有还原组合里挑唯一能算出值的那个，
   有歧义或都算不出值时保守维持原合并。12 张探针修复 10 张。
3. **星号几何仲裁**：深色算术的乘号画成 Verdana 星号，模板分常被字母 x 压过。以质心为圆心
   多半径圆周数墨臂（星号六条辐、x 四条对角臂，实测 6:4），模板判 x 而几何说星号时拨回。
   加号压制实验（十字验证过就无视 0.8 分数线）无独立贡献，简化掉。

算术类 81.64% → 85.66%（+4.02pp）；混合类 −0.58pp、数字 −0.12pp，净 +0.82pp。
`mvn -pl jkit-captcha test`：Tests run: 52，Failures: 0，历史门槛未改。

识别错误 20762 → 18842，识别失败 0。平均耗时下降 32%，来自 CaseVote 移除。

## 本轮落地的改动

1. **深色图算术/字母权威仲裁**（DefaultCaptchaSolver）：深色自动图过去一律按算术字母表分类，
   字母图被强套数字标签后裸数字算不出值触发重试、算式图运算符缺损，两条路都会在
   MinusInsert/OpRepair 里被包装成假算式。现在对同一组分割字形用算术与字母数字两套字母表各打
   一遍分，字母均值高出 0.05 以上判为字母图并翻转（实测字母图高 0.10 以上、真算术低 0.04 以上，
   两侧各有余量）；不翻转则维持算术路径，替代原来"算不出值再重试"的旧守卫。
   CaptchaRecognizer 里 MinusInsert/OpRepair 加类型闸，只服务 `ARITHMETIC` 结果。
   实测 +1.26pp，LETTERS +4.05pp，ARITHMETIC 不变。
2. **移除 CaseVote**：10 万张分层消融显示它净负（80.58% → 81.19%，移除后），翻对的少、翻错的
   多，且每张多花约 44 ms。连同只为它新增的 `TextModel.readReading` 一起删除，与阶段三
   InkLift/CaseResolver 的回滚同理。
3. **窄条字形几何仲裁**（DefaultCaptchaSolver.adjudicateNarrow）：小写 i 的点断（主茎列带垂直
   墨段数 ≥2）、大写 I 的上下衬线作为模板分之外的形状证据，修模板把 I/i 标成 l 的一类错误。
   数据集上≈中性，保留。
4. **0 的字高改判**：0 顶在大写线，明显矮于中位数的字形被标成 0 时改判 ranked 里最好的
   x 高度字母。数据集上≈中性（o→0 混淆主要发生在模型路径），保留。

大小写调参实验（PlateCase GAP 4→3、adjustCase 分差 0.14→0.18、CaseAlign 窄条家族保留模板字）
均被分层快评否决回退；剩余大小写错误（约 9% of 全部）的根因仍是 common_old.onnx 对大小写与
竖条/圆形字形的判别力，与阶段三结论一致：换/训专用模型是下一阶段的现实路径。
