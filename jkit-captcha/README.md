# jkit-captcha — 常规图片验证码识别

识别三类常规图片验证码：数字与大小写字母混合的字符型、带扭曲和线条噪点的干扰型、需要读出算式并算出结果的算术型。模板匹配用 JDK 的 `java.awt` 和 `ImageIO`。单帧图再由 ddddocr 的 ONNX 模型补字符（ONNX Runtime 1.15.1）。一般图用 `common_old.onnx`，大小写沿用模板。高至少 70 的窄幅蓝字用 `common.onnx`，大小写留在模型结果里。两个模型文件都打在本模块里，许可证是 Apache-2.0。OpenCV、Tesseract 通过 `CaptchaSolver` 接入。

源码与目标字节码为 Java 8。运行测试和命令行示例时加上 `-Djava.awt.headless=true`（Surefire 已配置）。

## 引入

```xml
<dependency>
    <groupId>com.alianga</groupId>
    <artifactId>jkit-captcha</artifactId>
    <version>2.0.5-SNAPSHOT</version>
</dependency>
```

编译期依赖 `com.alianga:jkit`，用来在示例和测试里调用 `SpecCaptcha`、`GifCaptcha`。识别本身不调用生成类。传递依赖 `com.microsoft.onnxruntime:onnxruntime:1.15.1`。

## 调用

```java
CaptchaRecognizer recognizer = CaptchaRecognizer.createDefault();

// 自动判断背景和类型
RecognizeResult result = recognizer.recognize(image);
System.out.println(result.summary());

// 已知是算术验证码时收紧字符集
RecognizeResult math = recognizer.recognize(image, CaptchaType.ARITHMETIC);
String expression = math.getExpression(); // 例如 14+8
Integer value = math.getValue();          // 例如 22

// 文件、字节、输入流
recognizer.recognize(new File("14+8.jpeg"));
```

`summary()` 形如 `ARITHMETIC text=14+8=? value=22 confidence=0.86 elapsedMs=15`。`elapsedMs` 是模板匹配阶段的整毫秒。测试表里的耗时用 `System.nanoTime()` 包住整次调用，含模型推理。

无参数运行 `CaptchaRecognitionDemo` 会生成一张 4 位 `SpecCaptcha` 并打印期望文本和识别摘要。传入图片路径则逐张识别：

```text
java -Djava.awt.headless=true -cp jkit-captcha.jar:jkit.jar:onnxruntime-1.15.1.jar \
    com.alianga.jkit.captcha.CaptchaRecognitionDemo 14+8.jpeg 9050.jpg
```

## 处理流程

1. 读成 `RgbImage`，用边框中位亮度判断背景。宽 68–96、高 26–34、灰底，并且白色像素大多贴着深色字芯时，按白边锯齿字处理。其余图：低于 80 为暗底；灰度落在 160–235、暗像素比例在 0.04–0.45、且白色像素超过 0.08 为空心描边；再其余为浅底。
2. 按背景选择分割器。`CaptchaType.AUTO` 时：暗底先按算术型识别，表达式无法解析且调用方没有限定字符集时，再按字符型重识别；空心归入 `DISTORTED`；浅底出现明显宽字符分裂时归入 `DISTORTED`，否则为 `ALPHANUMERIC`。指定类型后使用对应字符集。文本本身能解析成算式时仍会计算，与类型无关。
3. 分割得到单字图。每个字按长宽比缩放到 24×32 网格（最近邻，四周留 1 像素）。
4. 与字体模板做 Dice 系数匹配。模板在第一次识别时渲染并缓存。系统里有对应字体时使用 Verdana（粗体、粗斜体，一层 0.7 透明度，以及按空心描边和正弦位移画的变体）、Arial、Arial Black、DejaVu Sans、Liberation Sans、Times New Roman、Dialog。一个可用字体都没有时退到 `SansSerif` 粗体。宽、高都不超过 14×15 的小字只用实心模板，避免描边模板把细数字认成字母。
5. 置信度低于 0.50 的字丢弃。只对矮身字母（如 `a c e m n s v w y z`）做大小写校正：分差不超过 0.14，并且字高或字顶相对整行明显偏矮时取小写，明显齐大写线时取大写。宽 110–260、高 32–46 的图再按 SpecCaptcha 的基线收一次：字母顶不低于 10 时取小写；`a c e m n r s u v w x z` 的盒子顶到不超过 9、高至少 20、下沿不超过 33 时取大写。
6. 算术表达式去掉空格、`=`、`?` 和全角问号，只取第一个运算符（`+ - * / x X ×`）。整数除法截断。除零或非数字返回空结果。
7. 单帧图在模板没有算出算术值时，用 `common_old.onnx` 再读一遍，按模板的大小写对齐字符。模型每一帧只在当前字符集里取字：调用方用 `withAlphabet` 时用该字符集，字符型和干扰型只用字母和数字，算术型在此之外再允许 `+ - * / = ?`，因此不会把汉字或标点补进结果。模板和模型都只给出一个字符、而且忽略大小写后仍不同，就保留模板字符，这样 `learn` 进去的单字不会被模型换掉。高度至少 70、边框偏暗、蓝色笔画至少 400 个的图，按像素里存好的 RGB 把蓝笔画抽成白底黑字，透明通道不参与。宽度至少 260 的用 `common_old.onnx`，字母再转成大写；更窄的用 `common.onnx`，大小写留在模型结果里，模型返回空串时再退回 `common_old.onnx`。多帧 GIF 使用合成图上的模板结果。已经算出值的算术题保留模板串。深色图里单独出现的 `X` 会被当成乘号，这种蓝字图仍交给模型。
8. 宽 124–136、高 46–50、边框亮度中位数至少 220、暗像素至少 20 个的彩色字，正好是 130×48 时先按 easy-captcha 的槽位比对十套字形（`ocr/easy-plate.bin`）。命中只算在同一种颜色上，得分是命中像素减去没命中的像素，避免细笔画盖住粗笔画的一部分就胜出。五帧 GIF 按透明度节奏，每一帧只读完全不透明的那个字。静图上若 `=?` 两个字位都对上，并且整式得分高于字母读法，就按算式计算。平均重合低于 0.72 时改走下面的模型。模型用 `common.onnx`：静图先把右侧 38% 涂白，用数字和 `+ - x` 读一遍；读出的串是一道二元算式，并且字母读法并没有明显更可信时，按这道算式计算。加减号允许字母读法高出 4 分，乘号 `x` 只允许高出 0.55 分。否则在 487 个常用汉字（`ocr/easy-han.txt`）和字母数字里取平均分更高的一串。多帧里帧数正好是 4 时按常用汉字投票，其他帧数按字母数字投票。每一帧的字按时间步落到从左到右的字位，同一字位留下分数最高的那个字。

`RecognizeOptions.withAlphabet` 限定候选字符。`withExpectedLength` 只记在参数里，分割仍按图像结构进行。

## 各类型的预处理

暗底算术（样本 `14+8.jpeg` 等）：按颜色聚类前景，去掉与字色相同的细长干扰线，再做连通域。过宽的粘连块按几乎无墨的列切开。短横、等号用几何规则判定；十字形且模板分不够高时判为加号。模板把加号打到 0.85 以上时保留加号。

浅底字符（`9050.jpg`、`SpecCaptcha`）：暗墨用亮度，彩色字用饱和度。亮色字单独成块补进掩膜，避免被浅色背景丢掉。高度约 40 的图上，又矮又稀的色块当作干扰椭圆去掉。小墨点并回上下相邻的字。过宽的块按投影谷切开。宽 110–260、高 32–46 且调用方没有指定字符表时，候选里去掉 `0`、`1`、`O`、`I`、`l`。前两名模板分相差不超过 0.06 时，用同样字号和 0.7 透明度再比一次，并允许几个像素的平移。

白边锯齿字（问卷网，以及 `R8Y2.jpg`）：字是实心的，四周有一圈白边，字顶贴着上沿。只和另一批已标注样例的字形比，允许 2 像素平移；孔数不一致时扣 0.06。样例在 `src/main/resources/com/alianga/jkit/captcha/halo/`，测试图不在这批里面。

空心描边（合成样本）：抽出暗色笔画，做一次闭运算。左右间距不超过 4 像素、合起来仍像一个字宽的碎片拼回去。模板按同样的灰底、白填充和 2.2 像素描边生成，只和这组模板比。

扭曲：高度至少 48 时先按测试图的正弦做反向位移，再走浅底分割。横穿画面的扁线直接丢掉。斜体模板覆盖水平相位 8、48、88、128。粘连的细笔画（例如一串 `i`）仍会并成一块，整串因此缺字。

`SpecCaptcha` 的字是 Verdana 粗斜体、透明度 0.7。模板库里有一层同样混合方式渲染的字形。生成器字符表不含 `0`、`1`、`O`、`I`、`l`。

## 扩展

新类型实现 `CaptchaSolver`，再 `register`。后注册的排在前面，对它 `supports` 的类型生效。对 `AUTO` 返回 true 表示由该求解器自己判断类型。

默认字体对不上时，把单字图交给 `learn`：

```java
recognizer.learn(oneGlyph, 'Y');
```

它取图中最大连通域，归一化后加入模板库。白边锯齿字已经用上面的样例覆盖。还对不上的字体可以继续走 `learn`。

## 已知边界

- 问卷网白边字漏 1 张：`5HAB` 读成 `5HAb`。`R8Y2` 不在模板图里，这次是对的。
- ponytest 七张里六张整串正确，`2883` 读成 `1883`。miit 七张都正确。`9050` 正确。
- 江苏政务七张都正确。图是 284×80 的黑底蓝字，蓝笔画按存好的 RGB 抽成白底黑字后，用 `common_old.onnx` 并把字母转成大写。
- 山东是 220×80 的黑底蓝字，整串 6/7，字符准确率 96.4%。漏的是 `KVtJ`→`KVtj`。窄图用 `common.onnx`，大小写留在模型结果里。这一组平均 77.01 ms、最大 207.55 ms，最大的一次是首次加载 `common.onnx`。
- 生成算术固定漏 3 张：`29+18` 读成 `29t187`，`30+14` 读成 `30t47`，`5+4` 读成 `5t4e2`。加号被干扰线打断后，表达式不再可计算，结果是空。
- 扭曲整串 10/12，字符准确率 93.8%。漏 `TDRV`→`TDrv`、`zFRT`→`zFRt`。
- 合成空心描边 10/10。模板和分割都按同一套描边生成。
- `SpecCaptcha` 这次 4 位漏 5 张、5 位漏 1 张，都是大小写：`MQiA`→`MqiA`、`n8xC`→`n8XC`、`ThAf`→`THAf`、`u6uC`→`u6uc`、`GyRm`→`Gyrm`、`MWxF6`→`MWxf6`。
- `GifCaptcha` 每个字符只在部分帧里足够深。多帧里都偏暗的像素会合成一张图；合成结果短于 3 个字符时，改按各帧投票。这一次 5/6，漏 `QsaW`→`QsaN`。
- 130×48 的 `samples/spec` 和 `samples/gif` 整串大小写分别是 5/100 和 4/100。忽略大小写后都是 100/100。actionj 没有把大小写画出来。
- `samples/font/ransom/arithmetic` 整式 39/100。这套字体的 `+` 和 `-` 轮廓为空，图上没有运算符；两个数字是 100/100，画出来的乘号能对上。

## 测试

在仓库根目录执行：

```text
mvn -pl jkit-captcha test
```

`CaptchaRecognitionTest` 把完整失败明细写到 `jkit-captcha/target/captcha-accuracy-report.md`。`ArithmeticEvaluatorTest` 覆盖加、减、乘和整数除法（`8/2=?` 与 `9/2` 的结果都是 4）。
